# Module 5: Browser UI (`src/ui`)

Declarative React 19 + TypeScript browser user interface for **Roll for Shoes**, providing multi-campaign management, side-by-side character sheets with quota-safe portraits, interactive check resolution, post-roll skill advancement, persistent statuses, skill slots, JSON backup import/export, and Progressive Web App (PWA) installation.

---

## 1. What It Is

`src/ui` sits at the top of Roll for Shoes' strict one-way module dependency graph ([`../../docs/architecture.md`](../../docs/architecture.md)):

- **Top of the Downward Module DAG**: `src/ui` imports domain abstractions and entities exclusively through the public `index.ts` entrypoints of [`../dice`](../dice/index.ts), [`../checks`](../checks/index.ts), [`../character`](../character/index.ts), and [`../campaign`](../campaign/index.ts). Nothing in `src/*` ever imports from `src/ui`, and `src/ui` intentionally exposes no barrel `index.ts`—only the Vite browser entrypoint ([`../main.tsx`](../main.tsx)) mounts [`./App.tsx`](./App.tsx) and loads [`./styles.css`](./styles.css).
- **Uses Domain Rules—Never Re-Implements Them**: Every component in `src/ui` is a thin, declarative view over immutable domain objects. Components never compute check outcomes, margins, XP gains, non-`6` advancement upgrade costs, status totals, or skill slot limits/costs on their own; they always invoke fluent domain builders (`workspace.activeCampaign.character(id).makeCheck(...)`, `.advance(...)`, `Character.builder(...)`) and read computed domain getters (`checkResult.outcome`, `checkResult.margin`, `actor.finalTotal`, `pending.xpCostToAdvance`, `summary.availableSlots`, `summary.nextSlotXpCost`).
- **Root Dependency Injection (`AppProps`)**: `<App />` accepts both external side-effect boundaries via props—`diceRoller: DiceRoller` and `storageAdapter: StorageAdapter`—decoupling the entire component tree from concrete RNG (`RandomDiceRoller` vs. `StubDiceRoller`) and persistence (`LocalStorageAdapter` vs. `MemoryStorageAdapter`).
- **Responsive Layout & Hideable Default-Closed Sidebar**: [`./styles.css`](./styles.css) defines a zero-dependency responsive layout with automatic dark/light theming (`prefers-color-scheme`), `env(safe-area-inset-*)` standalone viewport padding, and coarse-pointer touch targets. Once an active campaign exists, [`CampaignSidebar`](./components/CampaignSidebar.tsx) defaults to hidden (`sidebarOpen = false`) so character cards (`minmax(min(100%, 380px), 1fr)`) and the check roller get maximum horizontal space—toggling a `300px` left rail on wide viewports (`>= 960px`) or a stacked top drawer on narrow viewports (`< 960px`), while automatically opening whenever no active campaign is selected.
- **Quota-Safe Portrait Encoding**: [`./portrait-image.ts`](./portrait-image.ts) validates, center-crops, and downscales uploaded character portrait images on an HTML `<canvas>` to at most `256×256` pixels (`image/webp` at `0.82` quality with `image/jpeg` fallback), keeping `data:` URLs compact enough for `localStorage` quotas and portable `.json` campaign exports. Characters without an uploaded portrait render deterministic 1–2 letter initials via `characterInitials(name)`.
- **Progressive Web App (PWA) Integration**: [`InstallAppButton`](./components/InstallAppButton.tsx) integrates both the emerging Web Install API (`navigator.install()`) and Chromium's `beforeinstallprompt` / `appinstalled` lifecycle events while automatically hiding itself in `display-mode: standalone`. In production builds, [`../main.tsx`](../main.tsx) registers `./sw.js` (generated by [`../../vite.config.ts`](../../vite.config.ts) alongside [`../../public/manifest.webmanifest`](../../public/manifest.webmanifest)) for offline precaching.

## 2. How to Use It

### 2.1 Mounting `<App />` in Production vs. Deterministic Sandboxes

In production ([`../main.tsx`](../main.tsx)), mount `<App />` with `RandomDiceRoller` (cryptographic `crypto.getRandomValues` RNG) and `LocalStorageAdapter` (`window.localStorage` persistence):

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { LocalStorageAdapter } from '../campaign';
import { RandomDiceRoller } from '../dice';
import { App } from './App';
import './styles.css';

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App diceRoller={new RandomDiceRoller()} storageAdapter={new LocalStorageAdapter()} />
  </StrictMode>,
);
```

Because `<App />` depends only on the `DiceRoller` and `StorageAdapter` interfaces, interactive demos, UI previews, or isolated sandboxes can mount the exact same UI with `StubDiceRoller` and `MemoryStorageAdapter`:

```tsx
import { Character } from '../character';
import { MemoryStorageAdapter, Workspace } from '../campaign';
import { StubDiceRoller } from '../dice';
import { App } from './App';

const storageAdapter = new MemoryStorageAdapter();
const seedWorkspace = Workspace.empty()
  .createCampaign('Heist at Midnight')
  .activeCampaign.addCharacter(Character.builder('Alice').build());

await seedWorkspace.save(storageAdapter);

// Deterministic d6 queue: first roll yields [6], opposition yields [3, 4]
const diceRoller = new StubDiceRoller([6, 3, 4]);

<App diceRoller={diceRoller} storageAdapter={storageAdapter} />;
```

### 2.2 Immutable Workspace State Flow (`commitWorkspace`)

`<App />` owns the single authoritative `Workspace` instance in React state:

1. **Async Load on Mount / Adapter Swap**: `useEffect` calls `Workspace.load(props.storageAdapter)`. Until resolved (or if `props.storageAdapter` changes), `workspace` derives to `null` and `<App />` renders a loading state. Load errors display in the top `role="alert"` banner and fall back to `Workspace.empty()`.
2. **Synchronous Render + Async Save (`commitWorkspace`)**: Child components never mutate domain objects in place. Instead, event handlers call fluent `Workspace` / `WorkspaceCampaignScope` / `CampaignCharacterScope` methods that return a **new** `Workspace` (`next !== prev`) and pass it to `onChange(next)`:

```tsx
// Inside App.tsx
const commitWorkspace = useCallback((next: Workspace) => {
  setError(null);
  setLoaded({ adapter: props.storageAdapter, workspace: next });
  void next
    .save(props.storageAdapter)
    .catch((err: unknown) => setError(toErrorMessage(err, 'Failed to save workspace.')));
}, [props.storageAdapter]);

// Inside a child component (e.g., CharacterCard.tsx)
const handleClearPortrait = () => {
  try {
    onChange(
      workspace.activeCampaign
        .character(character.id)
        .update((c) => c.withPortrait(null))
        .workspace,
    );
  } catch (err: unknown) {
    onError(err instanceof Error ? err.message : 'Unable to clear portrait.');
  }
};
```

Domain validation errors thrown synchronously by builders or methods are caught either locally inside modal/prompt forms (`dialogError` / `promptError`) or forwarded to `onError(message)` for the page-level alert banner.

### 2.3 Encoding Character Portraits & Fallback Initials

Use [`encodePortraitFile`](./portrait-image.ts) to convert a user-selected `File` from `<input type="file" accept="image/*" />` into a center-cropped `<= 256×256` `data:` URL before passing it to `CharacterBuilder.withPortrait(url)` or `character.withPortrait(url)`, and use [`characterInitials`](./portrait-image.ts) when `character.portrait` is absent:

```tsx
import { characterInitials, encodePortraitFile } from './portrait-image';

async function onFileSelected(file: File) {
  const dataUrl = await encodePortraitFile(file); // data:image/webp;base64,... (or image/jpeg fallback)
  const nextWorkspace = workspace.activeCampaign
    .character(character.id)
    .update((c) => c.withPortrait(dataUrl))
    .workspace;
  onChange(nextWorkspace);
}

// Fallback avatar text ("Alice Vance" -> "AV", "Bob" -> "B")
const initials = characterInitials(character.name);
```

### 2.5 Verification Workflow

Per project engineering rules ([`../../docs/architecture.md`](../../docs/architecture.md)), `src/ui` does **not** maintain a separate component unit-test suite; all game rules are exhaustively tested at the four pure TypeScript domain boundaries, while `src/ui` is verified via strict TypeScript typechecking and production Vite bundling:


### 3.2 Portrait Image Utilities ([`./portrait-image.ts`](./portrait-image.ts))

```ts
export const MAX_PORTRAIT_DIMENSION = 256;

export async function encodePortraitFile(file: File): Promise<string>;
export function characterInitials(name: string): string;
```

- **`MAX_PORTRAIT_DIMENSION` (`256`)**: Maximum width and height (in pixels) of encoded square character portrait images.
- **`encodePortraitFile(file)`**:
  - Rejects non-image MIME types (`!file.type.startsWith('image/')`), empty files (`file.size === 0`), broken images, zero dimensions, or unavailable 2D canvas contexts with descriptive `Error` messages.
  - Center-crops rectangular images to a square (`side = Math.min(naturalWidth, naturalHeight)`), scales down to `Math.min(256, side)` without upscaling smaller images (`imageSmoothingQuality = 'high'`), and revokes its temporary `blob:` URL in a `finally` block.
  - Returns a `data:image/webp` URL at quality `0.82`, falling back to `data:image/jpeg` at quality `0.82` when WebP canvas encoding is unsupported by the browser.
- **`characterInitials(name)`**: Trims `name`, splits on whitespace, takes up to the first two words, extracts the first Unicode code point (`Array.from(part)[0]`) of each in uppercase, and joins them (e.g., `"Alice Vance"` -> `"AV"`, `""` -> `""`).
